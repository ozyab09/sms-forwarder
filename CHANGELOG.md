# Changelog

Все заметные изменения проекта документируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [SemVer](https://semver.org/lang/ru/).

## [0.4.10] - 2026-09-09

### Изменено
- **Холодный старт больше не блокируется инициализацией хранилища**:
  `Prefs` инициализируются асинхронно (MasterKey + EncryptedSharedPreferences
  создаются в фоновом потоке). Первый доступ к настройкам из любого компонента
  (Activity/Receiver/Service) дожидается готовности — данные всегда корректны,
  а сам запуск приложения ускоряется.

## [0.4.9] - 2026-09-09

### Исправлено (аудит надёжности)
- **Краш на Android 12+**: запуск foreground-сервиса из бродкаста `PHONE_STATE`
  запрещён системой — старт обёрнут в try/catch, событие не теряется
  (сохраняется в файл очереди и уходит при следующем старте сервиса)
- **Переключатель «Без прокси» больше не ломает отправку**: direct-канал
  всегда первый и включён, его нельзя выключить; «смена прокси на Без прокси»
  корректно удаляет канал, а не создаёт сломанную запись
- **Предупреждение без `READ_CALL_LOG`**: если разрешение «Журнал вызовов»
  не выдано, UI явно сообщает, что пропущенные вызовы не будут пересылаться
- **UI больше не трогается из фоновых потоков**: рендер логов постится на
  main thread (логи пишутся из сервиса/ресиверов)
- **Защита от ReDoS**: block-regex компилируется один раз; паттерны с
  вложенными квантификаторами/альтернациями (риск катастрофического
  backtracking) отклоняются с предупреждением
- **«Стоп» очищает очередь** (память + файл на диске) — остановка сервиса
  больше не оставляет «хвосты», которые уйдут при следующем старте
- **Очередь не хранит тексты SMS на диске**, когда она пуста (privacy-first);
  при ненастроенном токене восстановленная очередь отбрасывается
- **`LogStore.clear` синхронизирован**; удалён мёртвый код
  (`Prefs.isProxyComplete`, `SmsForwarderApp.instance`)
- **`testAll` ограничивает параллельность** (4 потока) — нет всплеска потоков
  при большом числе каналов

### Добавлено
- **Автосохранение настроек** при уходе с экрана (токен/chatID не теряются)
- **Проверка обновлений не чаще раза в сутки** (было: каждый запуск)
- **Локализация**: строки теста каналов, предупреждений и диалога обновления
  перенесены в ресурсы (ru/en)

## [0.4.8] - 2026-09-09

### Добавлено
- **Перестановка каналов**: в списке каналов появились кнопки «выше/ниже» —
  порядок задаёт приоритет каскадной отправки (первый канал пробуется первым);
  «Без прокси» всегда первый и не двигается

### Изменено
- **Проверка связи тестирует все каналы параллельно** и показывает результат
  каждого канала (успех/ошибка с причиной) вместо остановки на первом рабочем:
  сводка в диалоге + посимвольные записи в логах

## [0.4.7] - 2026-09-09

### Исправлено
- **Очередь ретраев больше не блокирует новые события** (head-of-line blocking):
  упавшее сообщение не задерживает обработку последующих. Бэк-офф теперь per-event
  (15с → 30с → … кап 10 мин), после 8 попыток событие отбрасывается с записью в лог
- **Очередь не теряется при смерти процесса**: события персистятся на диск и
  восстанавливаются при следующем старте сервиса
- **Таймауты**: общий лимит на каскад каналов (120с) + `callTimeout` (30с) на
  каждый канал в OkHttp; `UpdateChecker` больше не утекает thread-pool
  (клиент закрывается)
- **Пропущенные вызовы**: принятые вызовы больше не пересылаются как пропущенные.
  Убран ложный fallback без `READ_CALL_LOG`, добавлен OFFHOOK-трекинг и
  подтверждение по CallLog с точным сравнением номеров (вместо substring)
- **ANR**: тяжёлая работа ресиверов (контакты, CallLog, фильтры, SIM) вынесена
  с main thread через `goAsync` + фоновый поток
- **SOCKS5 с логином/паролем** — явная ошибка в логе вместо тихого игнорирования
  авторизации (OkHttp не умеет SOCKS-auth)

## [0.3.0] - 2026-09-08

### Изменено
- **Убрана поддержка MTProto/TDLib** (нативная библиотека не грузилась на
  устройствах → краши): удалён `TdClient`, зависимость `lib-tdlib-android`,
  `Prefs.useMtproto`. Остался только Bot API (HTTPS)
- **Прокси только HTTP/SOCKS5**: убраны «Без прокси» и «MTProto-proxy» из
  выбора; переключатель «Использовать прокси» включает/выключает прокси
- **minSdk 29** — поддержка Android 10+

### Добавлено
- **Автообновление через GitHub Releases**: при запуске проверяется последний
  релиз, при наличии новой версии — диалог со скачиванием APK и установкой
  (`UpdateChecker`, `DownloadReceiver`, FileProvider)
- **Английская локаль** (values-en), `resConfigs("ru", "en")`
- **Тесты**: whitelist-логика SmsFilter, compareVersions; тесты в release-джобе CI
- **Облегчение дистрибутива**: ABI splits (arm64-v8a, armeabi-v7a) — два
  отдельных APK вместо одного большого

## [0.2.0] - 2026-09-08

### Добавлено
- **TDLib (MTProto) как основной канал отправки** (`TdClient`):
  - Авторизация бота через `CheckAuthenticationBotToken` (без телефона)
  - Прокси HTTP / SOCKS5 / **MTProto-proxy** (`AddProxy` + `EnableProxy`)
  - Сессия в `filesDir/tdlib` (пере-авторизация не нужна)
  - Fallback на Bot API при ошибке TDLib (`sendEither`)
- Переключатель режима `useMtproto` в настройках
- JitPack-зависимость `com.github.capullo-tech:lib-tdlib-android` (prebuilt AAR,
  нативные .so в jniLibs) — фиксированный коммит `11850efeb5`
- **Онбординг** (`OnboardingActivity`, ViewPager2): приветствие → токен → chat ID → готово
  - Автоопределение chat ID через `resolveChatId`
  - Повторные запуски сразу в `MainActivity` (`Prefs.onboardingComplete`)
- **Детальные фильтры SMS** (`SmsFilter`): режимы all / contacts / whitelist, block-regex
  - UI-секция «Фильтры SMS» (режим, белый список, regex)
  - `SmsReceiver` переведён на `SmsFilter.shouldForward`
- **Релизная сборка APK**: подписанный release-APK в CI, GitHub Release по тегам v*.
  Keystore передаётся через секреты (`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`)
