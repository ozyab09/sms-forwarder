# Changelog

Все заметные изменения проекта документируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [SemVer](https://semver.org/lang/ru/).

## [0.5.35] - 2026-09-14

### Исправлено
- **Release-сборка**: восстановлен случайно усечённый `ChannelSender.sendCascade` (хвост функции обрезан при удалении `sendDuplicate` в 0.5.22) — причина падения релизов v0.5.29–v0.5.33 (#90)
- Удалены остатки шаблона уведомлений (`etTemplateNotification`, префы, тесты) после удаления функции F10
- **Backup**: экспорт/импорт теперь включает `incomingCallsEnabled` и `outgoingCallsEnabled` — фича бэкапа настроек звонков была реализована наполовину (#94)
- `ChannelSenderTest`: добавлен отсутствующий `import runTest` — тесты не компилировались (#93)

### Изменено
- CI: PR-пайплайн запускает `lintDebug` вместе со сборкой и тестами; release-джоба прогоняет `testDebugUnitTest` перед `assembleRelease` (#91)
- CI: auto-tag job больше не пушит bump-коммит в main (блокировался branch protection) — версию бампит автор в PR, джоба только создаёт тег (#95)

## [0.4.14] - 2026-09-09

### Добавлено
- **Вкладка «О приложении»**: текущая версия рядом с кнопкой
  «Проверить обновления», ссылка на проект на GitHub, переключатель темы
  (светлая / тёмная / по системе), privacy-заметка
- **Выбор темы оформления**: сохранение в настройках (`Prefs.themeMode`),
  применяется во всех экранах (главный + онбординг) через
  `ThemeManager` / `AppCompatDelegate`

### Изменено
- **Архитектура: OkHttp-клиенты кэшируются по каналам** — раньше на каждое
  сообщение создавался новый клиент со своим thread-pool и закрывался после
  отправки (churn потоков + «холодные» TCP-соединения при пачке событий).
  Теперь клиент на канал живёт и переиспользуется (connection pool + keep-alive),
  кэш сбрасывается при изменении каналов
- **Архитектура: атомарная запись очереди** (`EventQueueStore`): снимок пишется
  во временный файл и переименовывается — при смерти процесса посреди записи
  старый файл остаётся целым, очередь не теряется
- **Архитектура: логика обновлений вынесена из `MainActivity`** в
  `UpdateManager` (throttle, ручная проверка, диалог, загрузка APK)

### Исправлено
- **Тёмная тема**: имя канала, IP/порт прокси и кнопки списка каналов больше
  не сливаются с фоном (были жёстко чёрные `@android:color/black`) — теперь
  цвета темы (`textColorPrimary`/`textColorSecondary`, иконки тонируются
  `colorControlNormal`)
- **Обновления «перестали приходить»**: метка «последняя проверка» ставилась
  ДО запроса к GitHub — при сбое сети или rate-limit проверки блокировались
  на 24 часа. Теперь метка ставится только при успешном ответе API;
  появилась ручная кнопка **«Проверить обновления»** (проверяет всегда,
  показывает результат тостом — актуально/ошибка)

## [0.4.9] - 2026-09-09

### Исправлено (аудит надёжности)
- **Краш на Android 12+**: запуск foreground-сервиса из бродкаста `PHONE_STATE`
  запрещён системой — старт обёрнут в try/catch, событие не теряется
  (сохраняется в файл очереди и уходит при следующем старте сервиса)
- **Переключатель «Без прокси» больше не ломает отправку**: direct-канал
  всегда первый и включён, его нельзя выключить; «смена прокси на Без прокси»
  корректно удаляет канал, а не создаёт сломанную запись
- **Предупреждение без `READ_CALL_LOG`**: если разрешение «Журнал вызовов»
  не выдано, UI явно сообщает, что пропущенные вызовы не будут пересылаться
- **UI больше не трогается из фоновых потоков**: рендер логов постится на
  main thread (логи пишутся из сервиса/ресиверов)
- **Защита от ReDoS**: block-regex компилируется один раз; паттерны с
  вложенными квантификаторами/альтернациями (риск катастрофического
  backtracking) отклоняются с предупреждением
- **«Стоп» очищает очередь** (память + файл на диске) — остановка сервиса
  больше не оставляет «хвосты», которые уйдут при следующем старте
- **Очередь не хранит тексты SMS на диске**, когда она пуста (privacy-first);
  при ненастроенном токене восстановленная очередь отбрасывается
- **`LogStore.clear` синхронизирован**; удалён мёртвый код
  (`Prefs.isProxyComplete`, `SmsForwarderApp.instance`)
- **`testAll` ограничивает параллельность** (4 потока) — нет всплеска потоков
  при большом числе каналов

## [0.4.7] - 2026-09-09

### Исправлено
- **Очередь ретраев больше не блокирует новые события** (head-of-line blocking):
  упавшее сообщение не задерживает обработку последующих. Бэк-офф теперь per-event
  (15с → 30с → … кап 10 мин), после 8 попыток событие отбрасывается с записью в лог
- **Очередь не теряется при смерти процесса**: события персистятся на диск и
  восстанавливаются при следующем старте сервиса
- **Таймауты**: общий лимит на каскад каналов (120с) + `callTimeout` (30с) на
  каждый канал в OkHttp; `UpdateChecker` больше не утекает thread-pool
  (клиент закрывается)
- **Пропущенные вызовы**: принятые вызовы больше не пересылаются как пропущенные.
  Убран ложный fallback без `READ_CALL_LOG`, добавлен OFFHOOK-трекинг и
  подтверждение по CallLog с точным сравнением номеров (вместо substring)
- **ANR**: тяжёлая работа ресиверов (контакты, CallLog, фильтры, SIM) вынесена
  с main thread через `goAsync` + фоновый поток
- **SOCKS5 с логином/паролем** — явная ошибка в логе вместо тихого игнорирования
  авторизации (OkHttp не умеет SOCKS-auth)
