## 1. Назначение

Android-приложение, которое пересылает **входящие SMS** и **пропущенные вызовы**
с телефона в **Telegram** через бота. Работает в фоне без заметных уведомлений,
не выгружается системой. Весь текст приходит в чат пользователя.

## 2. Термины

| Термин | Значение |
|---|---|
| **Бот** | Telegram-бот, созданный через @BotFather (выдаёт токен) |
| **Bot API** | Telegram Bot API (HTTPS) для отправки сообщений |
| **Web-proxy** | HTTP/SOCKS5-прокси для доступа к Telegram (обход блокировок) |
| **FG-сервис** | Foreground Service — фоновый сервис Android, защищённый от выгрузки |
| **Chat ID** | Идентификатор чата, куда слать сообщения (обычно ID владельца) |

## 3. Функциональные требования

### 3.1. Пересылка SMS
- Перехват **входящих SMS** в реальном времени (BroadcastReceiver `SMS_RECEIVED`).
- Для каждой: отправитель (номер и/или имя из контактов), текст, дата/время.
- Формат сообщения в Telegram:
  ```
  📩 SMS [2026-09-07 21:35]
  От: +7 900 123-45-67 (Имя)
  ---------------------------------------------------------------
  Текст сообщения…
  ```
- ⚠️ Фильтры SMS (по контактам / номерам / regex / чёрный список коротких
  номеров) **убраны** в v0.4.21 — пересылаются все SMS. Вместо фильтров —
  шаблоны сообщений и тихие часы.

### 3.2. Пропущенные вызовы
- Отслеживание входящих вызовов, которые **не были приняты** («пропущенные»).
- Для каждого: номер, имя из контактов, дата/время.
- Формат в Telegram:
  ```
  📵 Пропущенный [2026-09-07 21:33]
  От: +7 900 123-45-67 (Имя)
  ```
- Не пересылаются: принятые/исходящие вызовы, сброшенные пользователем
  (настраиваемо — см. раздел «Открытые вопросы»).

### 3.3. Настройки в UI приложения
Один экран с нижней навигацией (вкладки): «Настройки», «История», «Логи»,
«О приложении».
- **Токен бота** (обязательное поле, ввод-пароль, хранение в шифрованном виде).
- **Chat ID** (числовое поле; автоопределение по кнопке «Получить мой ID», см. 3.4).
- **Каналы отправки** — список: «Без прокси» (всегда первый, неотключаемый) +
  любое число прокси-каналов HTTP/SOCKS5 (тип, host, port, логин/пароль).
  Порядок списка = приоритет каскада; канал, через который прошла отправка,
  автоматически становится приоритетным (promote-on-success). Кнопка «Проверить
  связь» тестирует все каналы.
- **Переключатели**: «Пересылать SMS», «Пересылать пропущенные», «Тихие часы».
- **Шаблоны сообщений** — отдельные шаблоны для SMS и пропущенного вызова
  (`{sender} {name} {text} {time} {date} {type} {sim} {number}`), кнопки
  «Проверить» (превью), «Сохранить», «Сбросить» (пусто = стандартный формат).
- **Тихие часы**: интервал, в т.ч. через полночь (например 23:00–08:00).
- **Вкладка «История»** — события (SMS/вызовы) с поиском, фильтром по типу и
  статусом; клик по событию — полные детали (кому, бот, канал, полный текст).
- **Вкладка «Логи»** — кольцевой буфер (200 записей) INFO/OK/WARN/ERROR в памяти.
- **Статус сервиса**: «Работает / Остановлен», кнопка запуска/остановки,
  счётчик пересланных сообщений.
- **«О приложении»** — версия, тема (светлая/тёмная/системная), экспорт и
  импорт настроек (JSON, без секретов), проверка обновлений.

### 3.4. Проверка подключения и авто-ID
- Кнопка «Проверить связь»: проверяет все включённые каналы через `getMe`
  (параллельно, лимит 4) — сообщение пользователю НЕ отправляется, показывается
  результат по каждому каналу (успех/ошибка с причиной).
- Кнопка «Получить мой ID»: приложение отправляет боту команду и показывает
  полученный chat_id (пользователю достаточно написать боту `/start` один раз).

### 3.5. Запуск и работа в фоне
- **Автозапуск** с включением телефона (BootReceiver, `BOOT_COMPLETED`).
- **Foreground Service** (тип `dataSync` / `specialUse` на новых Android) — 
  приоритет против выгрузки, `START_STICKY` (перезапуск при убийстве).
- Повторная отправка при временном отсутствии сети (очередь, ретраи с backoff).
- **Без всплывающих уведомлений**:
  - канал уведомления FG-сервиса с важностью `IMPORTANCE_MIN`
    (невидимое уведомление; на Android 13+ пользователь отключает канал — 
    сервис продолжает работать);
  - никаких тостов/диалогов при пересылке;
  - опция «Отключить все уведомления» на Android 13+ (запрос `POST_NOTIFICATIONS`
    не показывается / отклоняется).

## 4. Нефункциональные требования

- **Минимальная версия Android:** 10.0 (API 29). **Target:** 34 (Android 14).
- **Язык:** Kotlin. **Сборка:** Gradle (Kotlin DSL).
- **Конфиденциальность:** SMS и номера не покидают устройство иначе как через
  Telegram-бота; логи — кольцевой буфер в памяти (200 записей), история событий —
  локальная БД Room, наружу не уходят. Токен бота и пароли прокси хранятся в
  `EncryptedSharedPreferences`; обычные настройки — в DataStore.
- **Надёжность:** очередь недоставленных сообщений с per-event ретраями
  (15с → 30с → … кап 10 мин, 8 попыток; упавшее событие не блокирует новые),
  персистентность очереди на диск (события не теряются при смерти процесса).
- **Размер:** APK ≤ 10 МБ.
- **Ограничение по батарее:** приложение запрашивает исключение из
  оптимизации батареи (`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) +
  инструкция для вендорных прошивок (Xiaomi/Huawei/Samsung — ручное разрешение
  автозапуска), т.к. без этого «не выгружаться» на всех устройствах невозможно.

## 5. Архитектура

> ⚠️ ASCII-диаграмма ниже — исходный черновик (2026-09-07). Актуальная
> архитектура — в §5.1.

```
┌─────────────────────────────────────────────────────────────┐
│  UI (MainActivity + Settings)                               │
│  - токен бота, chat id, прокси, переключатели, статус       │
└──────────────┬──────────────────────────────────────────────┘
               │ (EncryptedSharedPreferences)
┌──────────────▼──────────────────────────────────────────────┐
│  SMSReceiver  │  CallReceiver  │  BootReceiver               │
│  (SMS_RECEIVED)│ (PHONE_STATE + │  (BOOT_COMPLETED → старт   │
│               │  CallLog)      │   сервиса)                  │
└──────────────┬─────────────────┼────────────────────────────┘
               │                 │
┌──────────────▼─────────────────▼────────────────────────────┐
│  ForwardService (Foreground, START_STICKY)                  │
│  ├─ QueuedEvents (недоставленные → retry с backoff)          │
│  └─ TelegramClient (интерфейс)                               │
│        └─ BotApiClient  — Bot API HTTPS (+proxy)          │
└─────────────────────────────────────────────────────────────┘
```

- **SMSReceiver** — `RECEIVE_SMS`, срабатывает на каждое входящее SMS
  (не требует статуса Default SMS Handler).
- **CallReceiver** — `READ_PHONE_STATE` + `READ_CALL_LOG`: вызов звонил
  (`RINGING`) и завершился без ответа → событие «пропущенный».
- **ForwardService** — единственный владелец сетевого стека и очереди.
- **TelegramClient** — Bot API (HTTPS + прокси), единственная реализация (§7).

### 5.1. Фактическая архитектура (v0.4.x)

```
MainActivity (тонкий View) ──► MainViewModel (StateFlow + SharedFlow, MVVM)
        │                              │
        │                              ├─ Prefs (DataStore + EncryptedSharedPreferences)
        │                              ├─ ChannelStore / ChannelSender ──► TelegramClient
        │                              └─ EventHistory (Room)
SmsReceiver / CallReceiver / BootReceiver
        │
ForwardService (Foreground, START_STICKY, dataSync)
        ├─ SendQueue (FIFO + min-heap ретраев, per-event backoff)
        ├─ EventQueueStore (атомарная персистентность queue на диск)
        ├─ EventHistory (Room: статус/канал/chatId/бот/текст)
        └─ ChannelSender ──► ChannelClientFactory (кэш OkHttp по каналу) ──► Bot API
```

- **Каналы** (`telegram/Channel.kt`): «Без прокси» (direct, всегда первый) +
  N прокси-каналов; порядок = приоритет; promote-on-success.
- **Ретраи**: per-event 15с → 30с → … кап 10 мин, 8 попыток, затем событие
  отбрасывается и фиксируется в истории со статусом `dropped`.
- **Тихие часы**, **шаблоны**, **логи** (`LogStore`), **экспорт/импорт**
  (`SettingsBackup`), **обновления** (`UpdateChecker`/`UpdateManager`),
  **темы** (`ThemeManager`).

## 6. Права (permissions)

| Право | Назначение |
|---|---|
| `RECEIVE_SMS` | перехват входящих SMS |
| `READ_PHONE_STATE` | состояние вызова (звонок/сброс) |
| `READ_CALL_LOG` | подтверждение «пропущенный» (имя/тип) |
| `READ_CONTACTS` | имя отправителя/звонящего из контактов (обрабатывается на устройстве) |
| `INTERNET` | отправка в Telegram |
| `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_DATA_SYNC` | фоновый сервис (Android 14+) |
| `POST_NOTIFICATIONS` (Android 13+) | канал уведомления FG — пользователь может отключить |
| `RECEIVE_BOOT_COMPLETED` | автозапуск после перезагрузки |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | исключение из Doze |

## 7. Прокси и каналы

- **Bot API** — единственный путь: `api.telegram.org` (OkHttp) с поддержкой
  HTTP/SOCKS5 прокси.
- Каналы хранятся списком (JSON в secure-prefs), direct-канал всегда первый;
  каскадная отправка по порядку каналов, общий таймаут 120с (`callTimeout` 30с
  на канал).
- SOCKS5 с логином/паролем не поддерживается (OkHttp не умеет SOCKS-авторизацию) —
  в логе явная ошибка, а не тихое игнорирование.
- Legacy-настройки одиночного прокси (v0.4.x) автоматически мигрируют в канал.

## 10. Ограничения и риски (честно)

- **Android 14+ (target 34):** FG-сервисы с типами `dataSync`/`specialUse`
  требуют явных разрешений; «невидимость» ограничена — уведомление сервиса
  нельзя убрать полностью на Android 10–12 (только минимальная важность),
  на 13+ — пользователь отключает канал вручную.
- **Вендорные прошивки (Xiaomi, Huawei, Samsung):** система может убивать
  сервис, пока пользователь не разрешит «Автозапуск» в настройках вендора.
  Это решается инструкцией в onboarding + `START_STICKY` (не гарантирует
  на 100% на MIUI/HyperOS — известная боль всех таких приложений).
- **SMS:** на Android 10+ чтение входящих SMS через receiver работает всегда
  (не требует default handler); чтение *истории* SMS требует `READ_SMS`
  (в это ТЗ не входит, только входящие).
- **Блокировки Telegram:** при блокировке api.telegram.org HTTP/SOCKS5-прокси решают.
- **APK ~5–8 МБ** — лёгкий и быстрый.

## 13. CI/CD — GitHub Actions + SemVer (актуализировано 2026-09-13)

> ⚠️ Исходно ТЗ описывало GitLab CI — проект переехал на GitHub Actions.

### 13.1. Пайплайн (`.github/workflows/build.yml`)

| Job | Когда | Что делает |
|-----|-------|------------|
| `build` | `pull_request` | `assembleDebug` + `testDebugUnitTest` + `lintDebug`, загрузка debug APK в артефакты |
| `release-tag` («Auto tag») | `push` в `main` | читает версию из `libs.versions.toml`, создаёт тег `vX.Y.Z` (если нет) и запускает release-джобу |
| `release` | теги `v*` | `testReleaseUnitTest` + `assembleRelease` (подпись из секретов), артефакт APK, создание **GitHub Release** (`softprops/action-gh-release`) |

Правила запуска:
- Pull request → `build` (обязательно зелёный до мержа)
- Push в `main` → `release-tag` (автотег)
- Тег `vX.Y.Z` → `release`

### 13.2. SemVer (семантическое версионирование)
- Теги строго вида **`v<major>.<minor>.<patch>`** (пример: `v1.2.0`).
- Правила инкремента:
  - **major** — ломающие изменения (смена протокола, target API, архитектуры);
  - **minor** — новые функции (новый тип прокси, фильтры SMS, режим);
  - **patch** — фиксы и полировка (баги, переводы, иконка).
- Версия хранится в `gradle/libs.versions.toml` (`versionMajor`/`versionMinor`/
  `versionPatch`); тег `vX.Y.Z` создаётся автоматически при мерже в `main`.
- `versionCode` = `major*10000 + minor*100 + patch`.
- Версия bump'ается в том же PR, что и фича (patch — фиксы/мелочи,
  minor — новые функции, major — ломающие изменения).

### 13.3. GitHub Release
- На каждый тег `v*` джоба `release` создаёт **GitHub Release**:
  - имя: `vX.Y.Z`;
  - описание: автогенерируемые release notes (`generate_release_notes: true`);
  - ассеты: signed release APK (`app/build/outputs/apk/release/*.apk`).
- `CHANGELOG.md` — разделы `## [vX.Y.Z] - YYYY-MM-DD` (обновляется в том же MR, где bump версии).

### 13.4. Секреты репозитория (Settings → Secrets → Actions)
| Переменная | Назначение |
|---|---|
| `KEYSTORE_BASE64` | Подписывающий keystore (base64) |
| `KEYSTORE_PASSWORD` | Пароль keystore |
| `KEY_ALIAS` | Алиас ключа |
| `KEY_PASSWORD` | Пароль ключа |

Токен бота в приложении — это runtime-настройка пользователя (UI), не CI.

### 13.5. Раннеры
- GitHub-hosted `ubuntu-latest` + `actions/setup-java` (temurin 17, gradle cache)
  и `android-actions/setup-android`.
- Секреты в репозиторий не попадают — только через GitHub Secrets (masked).
